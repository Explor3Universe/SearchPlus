# Дуэль самоопровержения — практикум

Дополнение к закону 0 в `SKILL.md`. Правила дуэли живут там; здесь — иерархия доказательств, шкала весов, тест владельца и разбор типовых срывов. Если что-то здесь расходится с `SKILL.md`, прав `SKILL.md`.

## Центральная идея

Поиск находит **текст**. Текст описывает **прошлое** — момент, когда его написали, и **конкретный контекст** — объект, сегмент, условия, для которых его написали. Между находкой и ответом стоят два вопроса, которые поиск сам не закрывает:

1. **Как обстоит дело на целевую дату пользователя?**
2. **Про тот ли это объект, сегмент и условие, что нужны пользователю?**

У изменчивого факта есть **владелец состояния** — тот, кто уполномочен говорить, как сейчас, и кто обновляет источник при изменении вещи: оператор сервиса, ведомство, автор кода, издатель расписания, официальный реестр. Гайды, форумы, прайс-листы и справочники — свидетели прошлого: они переживают то, что описывают.

## Когда дуэль обязательна

Всё, что может измениться со временем:

- работа или существование сервиса, линии, магазина, проекта, компании;
- цены, тарифы, условия доступа, расписания, часы работы;
- статусы: deprecated, EOL, переименован, куплен, закрыт;
- поведение ПО, флагов, API между версиями;
- законы, правила, требования;
- «X существует» и «X не существует».

Дуэль не нужна для дат исторических событий, авторства, содержимого конкретного коммита, письма или выпуска. Там свой закон: читай сам первичный артефакт целиком.

## Пять проверок

### 1. Привязка

Прежде чем считать источник голосом ЗА или ПРОТИВ, сверь четыре координаты:

| Координата | Вопрос | Типовой перенос |
|---|---|---|
| Объект | Тот же продукт, тариф, рейс, версия, норма? | Новость о закрытии соседнего продукта той же компании; правило для другой версии API; другой тариф той же линейки |
| Сегмент | Для того же пользователя: откуда он, какой у него аккаунт, документ, регион, платформа? | Инструкция, написанная для пользователей другой страны; цена для корпоративных клиентов вместо частных; правило для резидентов |
| Время | Верно ли на целевую дату? | Базовое расписание без исключений на период; условие, которое изменится по анонсу до целевой даты |
| Условие | При каком режиме, профиле, настройке, тарифе? | «Бесплатно» на пробном периоде принято за «бесплатно всегда» |

Несовпадение по любой координате превращает источник в свидетельство о другом тезисе (`OFFSCOPE` в журнале). Он не подтверждает и не опровергает целевой тезис.

### 2. Смерть-запрос

Формула: `[точное имя объекта] + [глагол смерти] + [год]` на языке вопроса, на EN и на языке владельца, плюс новостная вертикаль.

Словарь глаголов смерти:

- RU: закрыт, отменён, прекратил, не работает, больше не, перестал, приостановлен
- EN: closed, shut down, discontinued, ceased, stopped, no longer, suspended, bankrupt
- HE: נסגר, בוטל, הופסק, פשט את הרגל
- ZH: 停运, 关闭, 停止运营, 破产
- DE / FR / ES: eingestellt, geschlossen, ausgesetzt / fermé, supprimé, suspendu / cerrado, eliminado, suspendido

Для условий доступа добавляй форму требования: `X requires …`, `X без … невозможно`, `X … required`.

Пройден, если результаты **прочитаны** (документы владельца из выдачи открыты), новости о смерти именно этого объекта не нашлись, **и** выполнена проверка 3.

### 3. Первичная живость — по слоям владельца

Иерархия доказательств для «верно на целевую дату»:

| Источник | Что доказывает |
|---|---|
| Страница исключений владельца на целевой период (сбои, статус, инциденты, известные проблемы, поправки) | состояние **на эту дату**; сильнее базового правила |
| Живая страница базового правила владельца (расписание, тарифы, документация, реестр) | работает **по базовому плану**; без проверки исключений — не «на вашу дату» |
| Обязывающий текст условия (документация, биллинг, условия использования) | условие доступа; сильнее лендинга и страницы тарифов того же владельца |
| Официальный канал публикации (бюллетень, реестр актов, официальный журнал, датированный release note) | изменение с даты вступления; сильнее справочных страниц, которые ещё не обновлены |
| Лендинг, страница тарифов, маркетинговая сводка | заявление владельца о себе; для условий — до сверки с обязывающим текстом |
| Свежая датированная новость о закрытии или изменении **этого объекта** | не работает / изменилось — сильнее гайдов; против живой страницы владельца, датированной позже события, проигрывает |
| Свежая датированная новость о работе | работает (вторично к владельцу) |
| Датированный гайд, форум | «работало на дату поста» |
| Недатированный гайд, форум, справочник, прайс-лист | ничего: справки переживают сервисы |
| Память модели | гипотеза: в изменчивых фактах ошибается в обе стороны |
| Сводка поискового инструмента, AI-обзор, пересказ страницы инструментом чтения без дословной цитаты | ничего: наводка, куда смотреть |

Классические ловушки:

- **«Есть тариф — есть сервис»**: строка в тарифной сетке остаётся после смерти сервиса.
- **Справочник с «часами работы»**: каталоги не обязаны убирать умершие конторы.
- **Свежая страница со старым фактом**: дата страницы ≠ дата факта.
- **Базовый план вместо даты**: расписание или документация верны «вообще», но на целевой период действует исключение, опубликованное отдельно.
- **Лендинг вместо условий**: страница тарифов обещает одно, документация биллинга требует другого.
- **Молчание базы**: базовая страница не упоминает случай пользователя, а исключение для него опубликовано отдельной страницей того же владельца.
- **Справка отстаёт от бюллетеня**: новое значение уже вступило в силу по официальной публикации, а справочные страницы и пересказы ещё показывают старое.

### 4. Датировка факта

Для каждого источника выпиши: когда написан, когда обновлён, какое время описывает. Недатированный источник не подтверждает изменчивый факт. Свежесть факта — максимум по датам источников-владельцев, а не по самой свежей странице.

### 5. Независимость

Откуда источник знает то, что пишет? Цитирует другой гайд? Переписывает вендора? Один предок = один источник.

## Шкала весов

| Доказательство | Вес для «верно на целевую дату» |
|---|---|
| Страница исключений владельца на целевой период | максимальный |
| Живая страница базового правила владельца, исключения проверены | максимальный |
| Обязывающий текст условия владельца | максимальный для условий доступа |
| Официальный канал публикации владельца | максимальный для правил, сборов и лимитов с даты вступления |
| Живая страница базового правила, исключения **не** проверены | высокий, но только «по базовому плану» |
| Свежая датированная новость о смерти **этого объекта** (привязка пройдена) | высокий |
| Отчёт госоргана, аудита, контролёра (реестр фактов) | высокий |
| Лендинг или страница тарифов владельца — для условий | средний: нужна сверка с обязывающим текстом |
| Свежая датированная новость о работе | средний |
| Датированный гайд, форум | низкий |
| Недатированный гайд, форум, справочник, прайс-лист | нулевой |
| Любой источник, не прошедший привязку | нулевой для этого тезиса |
| Сводка поискового инструмента или пересказ без цитаты | нулевой: наводка |
| Память модели | нулевой: гипотеза |

Правила взвешивания:

- Сравнивай **лучшее из ЗА с лучшим из ПРОТИВ**, а не количество с количеством.
- Шкала одна для обеих сторон: опровержение проходит привязку, датировку и класс так же, как подтверждение.
- Копии одного предка = один голос. Сто гайдов одного класса — один гайд.
- Равный вес — ничья. Ничья не публикуется как факт.

## Причина-запрос: каузальная проверка

У изменения состояния мира почти всегда есть **механизм**: реформа, закон, банкротство, отзыв лицензии, ремонт, смена политики, кризис, решение суда. Прежде чем выносить вердикт, поищи его запросом.

**Формула:** `почему/why/为什么 + X + закрылся/прекратил/отменили/shut down` + годы; для временных изменений — `X ремонт / works / maintenance / Sperrung + период`.

Что даёт причина:

1. **Объясняет весь класс разом**: и закрытие, и почему гайды врут, и почему справочники ещё показывают тарифы.
2. **Датирует границу**: всё, написанное раньше даты причины, — свидетель прошлого.
3. **Усиливает опровержение** с механизмом против любого числа безмеханизменных подтверждений.
4. **Проверяет тезис симметрично**: у живого сервиса есть носитель — оператор, лицензия, тариф, расписание, экономика.
5. **Объясняет исключение**: найденная причина временного изменения (ремонт, миграция, временное ограничение) подтверждает, что исключение на целевую дату реально, и показывает, когда оно кончится.

**Молчащее опровержение** — без причины и без первички — вес понижен. Но отсутствие причины не оживляет тезис автоматически: решает владелец, а не тишина.

## Тест владельца состояния

Владелец — не «любой официальный документ», а источник, который **обновляется при изменении вещи**. Вопросы:

1. Если X изменится завтра, изменится ли этот источник?
2. Отвечает ли он за целевую дату или описывает прошлое либо базовый план?
3. Говорит ли он о X по существу или упоминает попутно (тарифом, адресом, запретом)?
4. **Какой это слой:** базовое правило, исключение, обязывающее условие или маркетинг? Хватает ли его слоя для тезиса?
5. **Есть ли на странице отсылка** («здесь не отражено», «см. раздел», «условия») — и пройдена ли она?
6. **Заинтересованность:** что источник теряет, если тезис ложен? Владелец легитимен в операционных данных и нелегитимен в оценках о себе.
7. **Применяет ли источник правило сам** или только рассказывает о нём? Если официальные органы расходятся, решает тот, кто проверяет, списывает, выдаёт или взыскивает.
8. **Говорит ли он о случае пользователя** или молчит о нём? Молчание базовой страницы — повод искать исключения у того же владельца, а не основание применить общее правило.

Провал вопросов 1–3 — не владелец. Провал 4–8 — владелец, но проверка не закончена: не тот слой, не пройдена отсылка, не тот орган или случай пользователя не покрыт.

**Фильтр, а не запрет.** Официальные источники по умолчанию — сильный класс и частый владелец. Подозрение возникает при конфликте интересов, в оценочных вопросах и при расхождении между страницами одного владельца. В таких спорах обе стороны проходят полную проверку.

## Память — тезис без даты и без истории

«Все знают, что X работает», расписание, цена, синтаксис команды из памяти — тезис с нулевой поисковой историей. Он опасен дважды: уверенность в нём максимальна, поэтому он не попадает в очередь проверки, и он тиражируется между моделями как эхо. Такие тезисы чаще всего появляются **при написании ответа** — поэтому инвентаризация делается по черновику (фаза 6 в `SKILL.md`).

## Типовые срывы дуэли

Каждый срыв — класс, а не случай. Узнавай его по признаку.

| Срыв | Признак | Что делать |
|---|---|---|
| **Опровержение прицеплено снизу** | ПРОТИВ найден, упомянут оговоркой, рекомендация осталась | ПРОТИВ сильнее → рекомендация отменяется |
| **Спасение подменой** | «Официально нет, но де-факто…» без своей дуэли | Новая дуэль; максимум ничья |
| **Документ принят за владельца** | Тариф, приказ, POI подтверждают «работу» | Тест владельца, вопрос 1 |
| **Счёт штуками** | «Подтверждено 4+ источниками» без владельца | Счёт по классам |
| **Перенос с соседа** | Свидетельство про другой объект, сегмент или дату засчитано за или против | Привязка, проверка 1 |
| **Опровержение без проверки** | Недатированная сторонняя страница перевесила живого владельца | Шкала одна для обеих сторон; порядок во времени |
| **Ритуальный контр-запрос** | Запрос сделан, результаты не открыты; документ владельца в выдаче не прочитан | Контр-запрос закрыт только чтением |
| **Отказ по рангу** | Противоречие от слабого источника отброшено, а не проверено у владельца | Слабое противоречие — наводка на обязывающий документ |
| **Базовый план вместо даты** | Взято общее расписание или документация; страница исключений не открыта, отсылка проигнорирована | Слои владельца; отсылки обязательны |
| **Лендинг вместо условий** | Страница тарифов принята за условие при молчании или противоречии документации | Обязывающий текст сильнее лендинга |
| **Отказ по одному ограничению** | Кандидат отброшен, механизм нарушения не изучен | Ближний промах |
| **Слепота к соседнему решению** | «Варианта нет», хотя решение лежит за границей формулировки (соседний узел, другая категория, комбинация) | Перебор механизмов |
| **Тезис после инвентаризации** | Вывод, деталь из памяти или команда появились при написании и прошли без проверки | Инвентаризация по черновику |
| **Переложено на пользователя** | «Уточните сами», хотя владелец публикует ответ | Разреши у владельца |
| **Подсказка в вопросе к странице** | Ожидаемый ответ вписан в запрос к инструменту чтения | Нейтральный вопрос, дословные цитаты |
| **Сводка вместо источника** | Вывод взят из итога поискового инструмента или пересказа страницы; дословной цитаты нет | Сводка — наводка; утверждение — по цитате |
| **Молчание базы принято за правило** | Базовая страница не упоминает случай пользователя, и общее правило применено без поиска исключений | Поиск исключений у владельца; условие правила очерчивает его границу |
| **Старое значение при найденном новом** | Новое значение с датой вступления до целевой даты найдено, но подано как «не подтверждено», а старое — как основное | Проверка в официальном канале публикации; новое — вероятно действующее |
| **Не тот официальный орган** | Из двух расходящихся официальных источников взят первый попавшийся | Владелец — тот, кто применяет правило; неразрешённое требование — по строгому значению с объяснением |
| **Сторонний пересказ при недоступном владельце** | Официальная страница не открылась — и ответ построен на пересказах | Зеркала владельца, поиск по его доменам |
| **Угаданный адрес** | URL составлен по догадке, 404 принят за ответ | Адреса — из выдачи и ссылок |
| **Сегмент из окружения** | Свойства пользователя (страна, система, тариф) взяты из среды агента, а не из вопроса | Сегмент — из вопроса; остальное — названное допущение |
| **Ссылка не о том** | Под утверждением стоит ссылка на страницу с другим значением, объектом или датой | Инвентаризация сверяет ссылку с утверждением по цитате |

## Как выглядит выигранная дуэль

Инвентаризация с координатами целевой точки → смерть-запросы на языке вопроса, EN и языке владельца → результаты контр-запроса прочитаны, документы владельца открыты → причина найдена (если изменение было) → базовое правило и слой исключений на целевую дату сверены у владельца, отсылки пройдены, молчание базы о случае пользователя проверено поиском исключений, новые значения сверены с официальным каналом публикации → у отброшенных кандидатов проверены обходные механизмы → опровергнутое понижено, а не смягчено → замена подтверждена владельцем → по непроверяемому — честная ничья с конкретным способом проверки для пользователя.

Признаки: несущий тезис подтверждён владельцем на нужном слое; ни одно свидетельство не взято с соседнего объекта; ответ говорит простыми словами, что подтверждено, что нет и как проверить остальное.
